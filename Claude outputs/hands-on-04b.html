Article model with Pydantic

hands-on/article_model.py

# pip install pydantic-mongo pymongo

from pydantic_mongo import AbstractRepository, ObjectIdField

from pydantic import BaseModel

from datetime import datetime

from typing import Optional

 

 

class Article(BaseModel):

  id: ObjectIdField = None

  title: str

  url: str

  np_name: str

  date: datetime

  body: Optional[str] = None

  tags: list[str] = []

 

 

class ArticleRepository(AbstractRepository[Article]):

  class Meta:

    collection_name = "articles"

pydantic-mongo

Thin bridge between Pydantic v2 and pymongo. Install: pip install pydantic-mongo pymongo. No ODM magic — just typed serialisation.

ObjectIdField

Maps MongoDB's _id to a Python field. Defaults to None before insert; populated by repo.save().

AbstractRepository[Article]

Generic base giving you save(), find_by(), find_one_by(), delete() typed to your model.

Pydantic validation

Every field validated before MongoDB is touched. Wrong type raises ValidationError at construction time.

Why bother?

Raw pymongo returns plain dicts. A typed model gives you autocomplete, early type errors, and a single source of truth for the schema.

Step 5. pydantic-mongo bridges Pydantic v2 models with pymongo — no full ODM, just typed serialisation and a small repository interface. Article inherits from BaseModel: title, url, np_name are required strings; date is a datetime; body is optional; tags defaults to an empty list. The id field uses ObjectIdField which serialises MongoDB's _id BSON ObjectId into a Python-friendly form and defaults to None before the document is saved. ArticleRepository extends AbstractRepository[Article] — the only required class attribute is Meta.collection_name. In exchange you get save(), find_by(), find_one_by() and delete() that accept and return typed Article objects instead of raw dicts. Pydantic validates every field at construction time, so bad data raises a ValidationError before touching the database.
