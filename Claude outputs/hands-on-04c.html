Insert with repo.save()

hands-on/06-insert-with-model.py

from pymongo import MongoClient

from datetime import datetime

from article_model import Article, ArticleRepository

 

client = MongoClient("mongodb://root:example@localhost:27017/")

db = client["news_db"]

repo = ArticleRepository(database=db)

 

# Pydantic validates before touching MongoDB

article = Article(

  title="El paro baja en octubre",

  url="https://elpais.com/economia/paro.html",

  np_name="elpais",

  date=datetime(2024, 10, 1),

  tags=["economía", "trabajo"],

)

repo.save(article)

print(f"Inserted: {article.id}")

 

# Query returns typed Article objects

for art in repo.find_by({"np_name": "elpais"}):

  print(art.date, art.title)

repo.save(article)

Serialises the Pydantic model to BSON and calls insert_one. After the call, article.id is populated with the new ObjectId.

article.id after save

The repository mutates the model in-place, setting id to the inserted _id. Print or store it for later retrieval.

repo.find_by(filter)

Takes a pymongo filter dict, returns typed Article objects. Use art.title not art["title"] — IDE autocomplete works.

Raw dict vs typed model

Raw: doc["tittle"] — typo caught at runtime only. Typed: art.tittle — AttributeError and IDE underline immediately.

Step 6. With ArticleRepository wired up, inserting a document is creating a typed Python object and calling repo.save(). Pydantic validates every field at construction time — pass a string where a datetime is expected and you get a ValidationError before the database is touched. After repo.save(), the article's id field is populated in-place with the MongoDB ObjectId, which you can print or use for later lookups. find_by() takes a standard pymongo filter dict and returns a generator of Article objects — you access fields with dot notation (art.title, art.date) rather than dict subscript (doc["title"]), which means your IDE can autocomplete and static analysers can catch typos. The key contrast to drive home: raw pymongo returns dicts, so typos in key names surface only at runtime; typed models surface them at write time, in your editor.
